## Evidence classes

| Class | Meaning in this atlas |
| --- | --- |
| Public requirement | A standards body or public platform specification names the persistent-state behavior or memory class. |
| Published implementation example | A product maker, evaluator, or technical paper documents a concrete implementation or lifecycle behavior. |
| Vendor disclosure | An IP or product vendor publicly describes a capability, portfolio envelope, use case, or adoption claim. |
| Historical vendor context | A dated vendor-authored article or acquisition announcement explains product lineage or earlier market positioning. |
| Bounded inference | Sources establish the state requirement, but the proposed NVM placement or family remains an architecture hypothesis. |
| Open validation | The public record is not sufficient to make a target decision. |

## Public decision rules

1. Name the state before naming the technology.
2. Split a device into state objects; do not label an entire application with one memory family.
3. Treat update cadence, density, write energy, process devices, retention, recovery, and threat model as independent axes.
4. A vendor use-case page establishes a candidate fit. It does not close the target qualification gate.
5. Historical application language can explain portfolio lineage, but current product and target-process evidence govern the decision.
